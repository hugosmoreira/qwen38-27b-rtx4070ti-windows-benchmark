## CUDA proof

The retained canonical startup log reported:

```text
using device CUDA0 (NVIDIA GeForce RTX 4070 Ti)
offloaded 66/66 layers to GPU
CUDA0 model buffer size = 7974.14 MiB
CUDA0 KV buffer size = 136.00 MiB
CUDA0 RS buffer size = 149.62 MiB
CUDA0 compute buffer size = 37.27 MiB
```

The same log reported a 397.85 MiB `CPU_Mapped` model buffer. Therefore, the accurate claim is that all eligible layers were offloaded to CUDA0—not that the process uses zero system memory.

The loaded point-in-time snapshot was 8,944 MiB VRAM used and 3,051 MiB free. The server reached `model loaded` in 2,843.821 ms. These are startup observations, not peak measurements.

## OpenAI-compatible smoke result

The canonical [raw result](../raw/native-smoke-iq2-xxs-20260815T234835Z.json), generated by committed harness revision `924554a`, passed 3/3 checks. Server-reported generation rates for the tiny responses were 37.57, 43.81, and 43.40 tok/s. They verify that timing fields are available but are not publication-grade throughput estimates.

One earlier [failed raw result](../raw/native-smoke-iq2-xxs-20260815T234723Z.json) is retained. It passed 1/3 because `--reasoning-format none` left Qwen's empty `<think>` wrapper in strict answer content. Reasoning generation remained off; changing the parser to `deepseek` separated that wrapper and allowed exact validators to inspect only the answer.

## Exit decision

Phase 3 is complete:

- the official runtime and both archives are pinned and checksum-validated;
- startup logs prove CUDA0 rather than CPU-only or Vulkan execution;
- all 66/66 layers were offloaded;
- material launch flags are committed;
- the selected IQ2 model serves successful requests through a local OpenAI-compatible API.

Phase 4 should add one warm-up, at least three measured repetitions, continuous GPU/CPU/RAM telemetry, TTFT, and variance analysis without changing this configuration.
